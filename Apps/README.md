# Apps

One folder per app. A folder becomes an app the moment it contains an `_app.yaml`; there is nothing
to register by hand — `backends/routes/apps.ts` walks this tree and serves the result as
`GET /api/apps`.

On Val Town that walk is expensive: there is no filesystem there, so every folder listing and every
marker is an HTTP round trip. `Apps/_manifest.json` is that walk precomputed, generated by
`deno task manifest` and committed, exactly as the icon sprite is. **The folders remain the source
of truth** — locally the manifest is never read, and `deno task check` fails when it disagrees with
what is on disk.

## Adding an app

1. Make a folder anywhere under `Apps/`.
2. Copy `_templates/_app.template.yaml` into it as `_app.yaml` and fill it in.
3. Put an `index.html` beside it.

4. Restart the dev server — discovery is cached for the life of the process and `Apps/` is not in
   the `dev` watch list, so a page reload alone will not show the new app.
5. Run `deno task manifest`, and `deno task icons` if the app uses an icon that is not in the sprite
   yet. Commit both generated files with the app.

## `_app.yaml`

| Field         | Required | Meaning                                               |
| ------------- | -------- | ----------------------------------------------------- |
| `name`        | yes      | Sidebar label. Falls back to the folder name.         |
| `sort_name`   | no       | Sort key; falls back to `name`.                       |
| `description` | no       | Shown in search matching.                             |
| `updated`     | no       | `YYYY-MM-DD`. Drives the "recently updated" view.     |
| `icon`        | no       | Iconify name such as `lucide:list-checks`.            |
| `color`       | no       | Hex accent; tints the sidebar while the app is open.  |
| `appspace`    | yes      | Top-level grouping. Each appspace is a separate tree. |
| `sections`    | no       | Ordered path; each item nests under the previous one. |
| `tags`        | no       | Extra search terms.                                   |
| `store`       | no       | Namespace for saved data and tables. See below.       |
| `db`          | no       | Schema generation — `v1`, `v2`. See below.            |
| `entry`       | no       | File served for the app. Defaults to `index.html`.    |
| `children`    | no       | Sub-pages in the app folder, listed as rows under it. |

## `children`

A flat list of files in the app folder, each an entry point in its own right:

```yaml
children:
  - editor.html
```

Each becomes an indented row under the app in the sidebar, labelled with the filename minus its
extension, and opens at `/apps/<folder path>/<file>` — the same way `entry` opens. A child is
therefore an ordinary page, not a parameter: it decides what it shows. Deep links carry the
selection as `#app=<id>&child=<file>`.

Like everything else here it is unvalidated: a filename with no file behind it still produces a row,
and the failure only shows up in the preview.

## `store`

An app that needs to save something imports `/shared/store.js` and calls it:

```js
import { store } from "/shared/store.js";

const data = store();
await data.put("scene", { elements: [] });
const saved = await data.get("scene"); // null until something is written
```

There is no route to add and no backend file to write. `store.js` derives the app from
`location.pathname`, and `/api/data/` is one handler shared by every app. Values are capped at 10 MB
and reachable only through the same session cookie as the rest of the site.

`get`/`put` are JSON. For anything else, give the key an extension and use `getText`/`putText`:

```js
await data.putText("rows.csv", "a,b\n1,2\n");
```

The extension decides both how the value is served and how it is checked on the way in. A body that
does not parse is rejected with the parser's own message, so a truncated write fails at the call
rather than surfacing as a broken app later:

| Extension | Served as | Checked with |
| --- | --- | --- |
| `.json`, none, anything unlisted | `application/json` | `JSON.parse` |
| `.yaml`, `.yml` | `text/yaml` | `@std/yaml` |
| `.csv` | `text/csv` | `@std/csv`, holding every row to the first row's column count |
| `.md` | `text/markdown` | nothing — any text is valid |
| `.txt` | `text/plain` | nothing — any text is valid |

These are real parsers, not `shared/app-yaml.ts`. That module reads a deliberately tiny YAML subset
because `_app.yaml` is hand-written and stays small; this route sees whatever an app sends, where a
subset would reject valid documents. They are loaded from pinned URLs rather than bare specifiers —
see the remote-imports note in `AGENTS.md`.

`store:` names the folder that data lands in. It is deliberately not the folder path: an app's `id`
comes from the path and breaks on a rename, and saved data should outlive one. Leave `store:` out and
it falls back to `id`, which reintroduces exactly that fragility — so set it on anything that saves.

Storage is Val Town's blob store in production and `_other/blob/` locally, decided in
`backends/blob.ts`. Nothing about that reaches the app.

## `db`

`store:` saves a document; `db:` saves rows. An app that wants tables sets `db: v1` and adds two
files beside its `_app.yaml` — `schema.sql` and `queries.sql`, both templated in `_templates/`:

```sql
-- schema.sql
CREATE TABLE IF NOT EXISTS {todos} (id INTEGER PRIMARY KEY AUTOINCREMENT, text TEXT NOT NULL);

-- queries.sql
-- name: listTodos
SELECT id, text FROM {todos} ORDER BY id DESC;
```

```js
import { db } from "/shared/db.js";

const todos = db();
await todos.run("addTodo", ["milk"]);
const rows = await todos.rows("listTodos");
```

As with `store.js` there is no route to add and no backend file to write. Three things are worth
knowing before writing the first query:

- **The browser sends a query name, never SQL.** `run` names a block in `queries.sql` and the server
  runs the repository's copy of it. One endpoint can therefore be shared by every app without the
  session cookie being all that stands between a browser and `DROP TABLE`. Adding a query means
  editing the file and restarting.
- **`{todos}` is a token, not a table name.** Every app shares one SQLite database, so the server
  expands it to `<store>_<generation>_todos`. Declare every table in `schema.sql`; a token in
  `queries.sql` that is not declared there is an error at load. Index names need a token too —
  `CREATE INDEX IF NOT EXISTS {todos}_done ON {todos} (done)`.
- **`schema.sql` and `queries.sql` are read once per process.** Editing either needs a dev-server
  restart, the same as editing `_app.yaml`.

Changing a column means bumping `db:` to `v2`: the new generation gets empty tables and an optional
`migrate.sql` copies the old rows across, naming the previous generation's table as `{prev.todos}`.
It runs once and is recorded in `sites5_migrations`. Adding a nullable column needs no bump — put an
`ALTER TABLE ... ADD COLUMN` below the `CREATE TABLE` in `schema.sql`.

The database is Val Town's SQLite in production and `_other/sqlite/apps.db` locally, decided in
`backends/sqlite.ts`. Nothing about that reaches the app.

The folder path on disk does **not** decide where an app appears — `appspace` and `sections` do. A
folder at `Apps/sandbox/todo3/` with `sections: [main]` shows up under **main**.

## Sections

`sections-metadata.yaml` gives a section its icon, colour, and sort order. Sections referenced by an
app but missing from that file still appear, just with defaults. Serving is by URL, not by folder:
every app is reachable at `/apps/<folder path>/`.

## Nothing here is validated

`_app.yaml` is read by a small hand-written parser (`shared/app-yaml.ts`) and every field falls back
silently, so a typo produces a misplaced app rather than an error. A missing `appspace` becomes an
appspace literally called `default`; an `appspace` or section name that is absent from
`sections-metadata.yaml` renders with a default icon and no colour — which is exactly what a
misspelled name looks like. Check the sidebar after adding an app.

An app's id is its folder path, slugged. That id is the `#app=<id>` deep link and the key used by
Recently opened, so **renaming or moving a folder breaks existing links and drops the app from that
view.**

## Reserved names

Folders starting with `_` or `.` are skipped by discovery, which is why `_templates/` is not an app,
and why `_shared/` can hold code that apps import without becoming one itself. `_manifest.json` is
generated; edit the `_app.yaml` files and rerun `deno task manifest` rather than the file.
